# 隐私与公开范围

开源代码、运行档案和公开站点是三个不同范围。默认仓库只提供源码、说明及合成模板；不会因为加入在线体验链接，就把本机档案复制进GitHub。

| 内容                                           | 默认处理                               |
| ---------------------------------------------- | -------------------------------------- |
| 源码、规则、合成示例、通用部署模板             | 可以进入仓库                           |
| 在线体验域名                                   | README主动公开；它会将仓库与该站点关联 |
| SSH私钥、授权码、API密钥、Cookie及浏览器登录态 | 不提交、不通过发布工具上传             |
| 发件邮箱、服务器连接配置、本机绝对路径         | 留在本机配置中；不进入源码包           |
| work档案、首次预测、行情缓存、训练数据、日志   | 默认忽略，不打包到源码仓库             |
| 真实视频截图、生成HTML、网站部署包             | 默认不进入源码仓库；网站发布另行处理   |

域名和DNS是公开网络信息；访问者可能通过域名查询服务器公网地址。提供网站链接不等于提供SSH登录权限，但会提高站点及其中内容的可发现性。

## 网页与图片需要单独审查

SSH发布器只允许首页和已登记JPEG，拒绝常见凭据、本机路径、个人QQ邮箱及内联位图。源图片仍需人工检查：字符串扫描不能识别图片里的头像、评论昵称、推荐内容、通知、个人资料或文字。完整浏览器截图可能包含这些区域，不能声称已经完全匿名化。

公开展示应优先使用只包含必要视频画面的证据图。若为公开展示制作裁切或遮挡版本，应与本机原始证据分开保存，分别登记SHA-256及处理说明；不要覆盖原图或把处理图冒称原图。本版本不自动识别人脸或完成截图匿名化，也不会对现有图片自动作上述处理。

在线站点中的视频及截图是第三方内容；MIT代码许可证不转授它们的权利。链接或引用不代表被观察者认可项目。真实截图、数据或报告的再发布范围需要单独核实，参见NOTICE.md。

## 发布前实际检查

1. 只从干净源码目录初始化Git仓库，运行npm run check。
2. 审查git status及git diff --cached --stat；.gitignore不影响已经被跟踪的文件，也不是访问控制。
3. 运行npm run release:check。检查器会读取实际Git索引和未忽略文件，只报告文件名与规则，不回显匹配值。
4. 不要在Issue、Actions日志或示例里粘贴真实运行配置。问题复现使用合成输入。
5. 若凭据已经公开，应在对应服务撤销或轮换；只从当前版本删除文件不能撤回Git历史与他人副本。

仓库扫描是辅助措施，并非“没有任何隐私风险”的保证。网站原图、既有Git历史和外部日志不在源码ZIP扫描范围内。
